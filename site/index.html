What it does

Both directions

Claude Code leads and Codex works, or the other way round — terminal or desktop app.

Picks the model

A five-question difficulty score → agent, model and effort, with the odds; learns from every ccx verify.

Cheap starts

Slim sub-agent start-up and the same sub-session continued within an hour, so the cache stays warm.

Shared memory

Only the other side's new lines arrive at session start; a project layer both tools see.

Resumable

Quota stop, crash or closed window: ccx task resume picks up the same session.

Receipts

Every run's tokens and cost; a dashboard of what delegating actually saved.

How it works

  1. ScoreFiles, coupling, clarity, risk, novelty → difficulty 0–10.
  2. RouteCheapest rung whose success odds clear the bar; an escalation path if it stalls.
  3. RunThe other agent works headless in your folder; edits can be undone or kept on a branch.
  4. CheckYou look at the diff, then ccx verify — routing calibrates to your work.

Questions

Doesn't a second agent cost more tokens?

Only for tiny tasks — then ccx tells you to do them yourself. Otherwise the sub-agent runs on a cheaper model than your lead and starts slim; the dashboard shows the difference from your own runs.

I'm on a subscription, not the API. Does this apply?

Yes: costs are shown at API prices so runs are comparable, and the dashboard also shows how much of each tool's quota went where. When one tool runs out, the work moves to the other.

Is it safe to let a sub-agent edit files?

Edits stay in the task's folder, every write run is snapshotted for ccx undo, and --mode read or --worktree keep your tree untouched. See SECURITY.md.

Which tools are supported?

Claude Code and Codex CLI, tested on a real machine in both directions. Gemini CLI and DeepSeek-backed Claude Code are adapted but not yet run for real.
