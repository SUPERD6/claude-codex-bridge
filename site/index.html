Seven things it does

1 · Each other's lead and sub-agent

Claude Code or Codex leads; Gemini CLI and DeepSeek (through Claude Code) take work. One adapter per CLI; ccx agents lists what each can do.

2 · Two models talking

ccx ask for the other vendor's second opinion, ccx resume to follow up in the same sub-session, ccx send into a live Codex session. ccx discuss: 2–3 vendors talk a costly decision through (stand-ins only so far).

3 · Shared memory

A personal layer (your hub) and a project layer (.ccx/); only the other side's new lines arrive at start; ccx handoff passes the baton, ccx fresh starts a fresh conversation.

4 · Splitting the work

Five questions → agent, model, effort and the odds; it says so when doing it yourself is cheaper or the task should be split. ccx batch, ccx q, resumable.

5 · Cheap and fast

Slim sub-agent start-up; ccx lead (--breakdown / --cache / --suggest) shows what the lead re-reads each turn; ccx sum trims big outputs.

6 · No drop in quality

ccx reruns the check (--check); another vendor reviews the diff (--review); every run gets a verdict (--reason), unjudged ones a probable one; ccx trial for a week-long comparison.

7 · You stay in control

Dry run and backups before config changes; ccx undo; --mode read, --worktree; sub-agents can't delegate further; ccx ui shows everything, read-only.

Receipts

Tokens and cost of every run; ccx report builds a dashboard. See a sample (stand-in data).

Questions

Doesn't a second agent cost more tokens?

It can. In the measurements, a small task saved something only when the lead answered as soon as ccx's check passed; a lead that reran the tests itself paid for the sub-task on top and waited longer. Most of the money goes on the lead re-reading its own conversation, which is what ccx lead, ccx sum and ccx fresh are for.

I'm on a subscription, not the API. Does this apply?

Yes. Costs are shown at API prices so runs can be compared; the dashboard also shows how much of each tool's quota went where. When one tool runs out, the work moves to the other.

Is it safe to let a sub-agent edit files?

Edits stay in the task's folder, every write run is snapshotted for ccx undo, and --mode read or --worktree keep your tree untouched. Details in SECURITY.md.

Which tools work?

Claude Code and Codex CLI can lead or work, tested for real in both directions. DeepSeek through Claude Code is calibrated on real tasks; Gemini CLI is adapted but hasn't run for real; both only work as sub-agents.

Why the new name?

The old name, claude-codex-bridge, was nearly the same as another project's (SeemSeam/claude_codex_bridge), and it's no longer just two tools. The command is still ccx; the old address redirects.
