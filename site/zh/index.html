七件事

1 · 互为主子

Claude Code、Codex、DeepSeek（dsh，或经 Claude Code）谁当主都行，三家也都能接活。Gemini CLI 有子智能体适配器，没真跑过。每家一个适配器，ccx agents 列出能力和测过的版本。

2 · 两个模型直接对话

ccx ask 问另一家第二意见，ccx resume 在同一个子会话追问，ccx send 发消息进正在跑的 Codex 会话；ccx discuss 让 2–3 家不同厂商讨论选错代价高的决定（两家和三家都真跑过）。

3 · 共享记忆

个人层（hub）和项目层（.ccx/）；开局只推对方新写的几行；ccx handoff 换主接力，ccx fresh 换新对话。

4 · 分工合作

5 个问题打出难度 → 选智能体、模型、强度；自己做更划算或该先拆就直说。ccx batch、ccx q 并行，断了能续。

5 · 省和高效

子智能体精简启动；ccx lead（--breakdown / --cache / --suggest）看主导每轮重读什么；ccx sum 压缩大段输出。

6 · 不掉质量

ccx 自己重跑验收（--check）；另一家模型独立审查（--review）；每次记对错（--reason），没人判的按证据记“大概对/错”；ccx trial 一周对比。

7 · 不丢可控

改配置先预演、先备份；ccx undo 撤回；--mode read、--worktree 不动工作区；子智能体不能再派；ccx ui 只读看全局。

有账可查

每次运行的 token 和花费；ccx report 生成看板。看示例看板（假数据）。

怎么连起来的

  1. 打分改几个文件、跨几个模块、目标清不清楚、风险、要不要新设计 → 难度 0–10。
  2. 选档成功率够高的档位里挑最便宜的；不值得派就让你自己做。
  3. 运行另一家在你的文件夹里后台干活；ccx 重跑验收命令，可选另一家审查。
  4. 验收你看一眼 diff，再 ccx verify；选模型按结果校准。

常见问题

多一个智能体，不是更费 token 吗？

有可能。实测里，小任务只有在主导看到 ccx 验收通过就直接答复时才省；主导再自己跑一遍测试，就是多花子任务的钱、多等十几秒。钱主要花在主导每轮重读自己的对话上，ccx lead、ccx sum、ccx fresh 管的是这一块。

我用的是订阅，不是 API，也适用吗？

适用。花费按 API 价格折算，方便比较；看板也会显示每个工具的额度用在了哪里。一边额度用完了，任务会换到另一边（目前只有模拟测试）。

让子智能体改文件安全吗？

只能改任务所在的文件夹；每次可写运行都会拍快照，可以 ccx undo；--mode read 或 --worktree 不会动你的工作区。详见 SECURITY.zh.md。

支持哪些工具？

Claude Code、Codex、DeepSeek（dsh，或经 Claude Code）都可以当主也可以当子，真机测过。Gemini CLI 按文档写了适配器但没真跑过，只能当子智能体；经 Claude Code 的 Kimi、GLM、Qwen、OpenRouter 配好了，没测过。

名字为什么改了？

原名 claude-codex-bridge 和另一个项目（SeemSeam/claude_codex_bridge）几乎同名，而且现在不只两家。命令仍是 ccx，旧地址会自动跳转。
