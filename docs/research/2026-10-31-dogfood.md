# Dogfood: what the real hub's ledger shows for 10-24 to 10-30 (2026-10-31)

English · [中文](2026-10-31-dogfood.zh.md) · [all reports](README.md)

> **Real use, not a controlled experiment, data from building ccx itself:** one person's hub during the week ccx
> was being built and measured. Most runs are ccx testing itself; the 5 real-work runs span 4 folders, 3 of them
> outside the ccx repository. No comparison arm, no hidden tests. Counts and costs only: no paths, labels or project
> names.

## In one line

In 7 days the real hub recorded 283 ccx runs and 64 reviews ($8.17 API-equivalent), but **only 5 runs were real work
outside ccx's own testing** ($2.88, in 4 folders). The rest were evaluations and trials (245), probes and acceptance
checks of fixes (32) and an ad-hoc test in a temp folder (1), all run against the real hub. Those 5 runs are 3–5
tasks (see Limits). There is still almost no
real-use data. Of the 5 real runs, 4 had a check, 4 were reviewed, and the lead later judged 3 right and 2 unfinished.

## Method

- **Source.** The hub's ledger (`<hub>/ccx/ledger.jsonl`), read only, from 2026-10-24 00:00 to 2026-10-31 00:00 at UTC−4 (the
  machine's local time that week, fixed in the script so a rerun elsewhere agrees). 598 rows: 347 runs and 251 events (208 verify, 37 dismiss, 6 other). The last row is from 10-30 evening.
- **Groups** (by label and folder, a fixed rule in `scripts/research/dogfood.py`; a review joins its run's group):
  eval/trial (`eval-*`, `f1-trial*`, `calib-*`, or run in an `f1-trial` or `ccx-7c-*` evaluation folder);
  probe/acceptance (`selftest`, `quota-probe`, `probe-*`, `startup-probe`, `E8 accept`, `live-ds*`, `two-way*`,
  `untried*`, `discuss:*`, `desktop-*`, the `*-real` checks of a fix); temp folder (none of those, run in a temp
  folder); real work (the rest). A run judged more than once counts its last verdict; 17 verdicts in the window
  are on runs from before it and are left out.
- **Re-run it:** `python scripts/research/dogfood.py <hub>/ccx/ledger.jsonl`. The output for this window is
  [data/2026-10-31-dogfood.json](data/2026-10-31-dogfood.json). It has counts only, and a folder is counted, never named.
- **Cost** is the ledger's API-equivalent USD (`ae_usd`). Codex and Claude actually ran on subscriptions.
- This report spent $0 (the plan allowed about $0.5 for it).

## Failures and re-runs (all 283 runs)

- Status error: 12 (kinds: auth 1, error 3, interrupted 6, over budget 2); blocked 3; partial 6.
- Review found issues as the final kind (`review_issues`): 23.
- Climbed to another rung: 5. Resumed or fix-round chains: 4.
- Verdicts on these runs: 213 judged (144 right, 24 wrong, 17 "probably right" soft verdicts, 28 dismissed). A
  verify event does not record who wrote it; 186 of the 213 are on eval/trial runs, so most were probably written by
  the evaluation scripts (`ccx verify` with the hidden-test result), not by a person. The 17 soft verdicts are ccx's
  own.

## The lead's token saving

**Unknown.** For a delegated run the ledger does not record the lead's tokens: 78 runs are linked to a lead
session, but its usage lives in the lead's own session files, which this report did not read. The only lead usage
in the ledger is 3 `selfrun` rows from one `ccx trial` on 10-25 (the lead doing a task itself, for comparison:
Opus 5.5, $21.92 in all, not counted in the $8.17 above). Three tasks of one trial give no saving figure. The measured saving is
still the one from the evaluations ([hc1](2026-10-29-hc1-holdout.md)).

## Limits

- **Not real use, mostly.** 278 of the 283 runs are ccx testing itself on the real hub. The 5 real runs are too few
  for any rate, so they serve as examples.
- **One person, one machine, one week**, while ccx was being built: nothing here generalises to other users.
- **The 5 real runs may be fewer tasks.** The DeepSeek CLI → Claude run had no label, check or review and ran
  about 12 hours after that adapter was merged: it looks like a first try. Two runs share one label 3 minutes apart
  (the second took 11.5 s): likely the same task run again. So 3–5 real tasks.
- **Groups are told from labels and folders.** An unlabeled ad-hoc test outside a temp folder would count as real
  work. The temp-folder group may hold real work started in a temp folder.
- **No ground truth.** The lead's `ccx verify` is a judgement, not a hidden test.
- **The H11 trial was void** (release plan), so this is not a trial result.
