# 外部基准 pg1：polyglot 30 道 Python 题，自己做 vs ccx vs 直接派（2026-10-31）

[English](2026-10-31-polyglot-pg1.md) · 中文 · 回到[研究报告](README.zh.md) · [计划](2026-10-30-polyglot-slice-plan.zh.md)
（规则在运行前定好）

**外部基准 polyglot 30 题（Python）：派给最便宜档 12/30，自己做 25/30，每次成功贵约 3 倍。小而接口严格的题别派；省钱只出现在
自己做较贵的仓库任务上。**

三条结论：

1. **这类单文件小题，派给最便宜档既错得多，每次成功又贵约 3 倍。** 这不是说 ccx 整体变差，也和
   [hc1](2026-10-29-hc1-holdout.zh.md) 不矛盾：派活省钱要同时满足“自己做本身贵”和“子智能体一样对”两条。hc1 的仓库任务两条都满足，
   pg1 两条都不满足。
2. **贵是因为题小，不是因为题难。** ccx2 的花费有 82% 在主导侧（写 brief、等待的那次调用、验收）。光主导侧每题中位就是 $0.035，
   已经超过自己做完整道题的 $0.027。就算子智能体每题都做对，ccx2 每次成功也要 $0.046，自己做是 $0.037。没有任何派活前能算出的
   特征能预测子智能体会在哪题失败。
3. **审查和修复轮没起作用，档位从未上升。** ccx2 的 check 跑的是子智能体自己写的 `test_own.py`：30 个单元里 30 个“通过”，包括隐藏
   测试失败的全部 18 个。所有路由都是 Codex gpt-6-luna low。

## 方法

- **选题**：aider polyglot 基准（commit 7e0611e，2024-12-22）里的 30 道 Python 题，选题时不看任何解法：aider 最难的 225 题
  （2024 年 7 个模型里最多 3 个做对）中有 34 道 Python，按（Exercism 难度，测试数）去掉最低的 4 道。题单和每题理由在
  `scripts/eval/polyglot_selection.json`，任务集在 `scripts/eval/tasks_polyglot.py`。
- **单元看到什么**：一个全新的单提交仓库，只有解法桩文件（没有测试、`.meta/` 和历史），加上题目自己的说明和一段简短附加说明
  （改哪个文件、保留名字、只用标准库、测试是隐藏的）。
- **三组**，说明、隐藏测试和隔离环境都相同：

| 组 | 谁来做 |
|---|---|
| `self` | 主导 Claude Code Sonnet medium 自己做 |
| `ccx2` | 同一个主导交给 ccx（省钱档：先 Codex gpt-6-luna low，ccx 的 `--check` 失败才升一档）；练习题没有能点名的测试文件，所以主导让子智能体写 `test_own.py`，再把它当 `--check`；另一家的模型审查 |
| `direct` | 没有主导：`ccx run` 直接派给 Codex gpt-6-luna low，有审查，没有 `--check`，不升档 |

- **一轮**（tag `pg1`，运行 20261031-145737Z，ccx 固定在 5d4bd01，codex-cli 0.164.0，Claude Code 2.1.309），90 个单元，
  `--arm-order balanced`（每题三个单元连着跑）。Codex 的 Windows 沙箱是 **unelevated**（单单元预跑 pg0 是 elevated）；这个设置
  来自运行配置，结果行里没有记录。更早一次中止的尝试（沙箱凭据失效）不用。
- **评分**：题目的测试文件是隐藏的；只把解法文件复制进一个带测试的新文件夹。做对 = pytest 恰好通过该题的测试数。**只有一次机会**：
  不像 aider（两次，第二次能看到报错），评分前谁都看不到隐藏测试。
- **两种口径**都给：全部 30 题，以及只算干净行（`env_clean`，即 `r5.py summary` 的口径）。有 3 行不干净，原因是运行时看到机器上
  有别的进程（其他会话的测试和 ccx 运行）：

| 干净口径排除的行 | 做对 | 影响 |
|---|---|---|
| `pg-book-store` self | 对 | 只影响计时，评分不变 |
| `pg-book-store` ccx2 | 错 | 只影响计时 |
| `pg-scale-generator` direct | 错 | 只影响计时 |

所以干净口径每组 29 个单元，self–ccx2 有 29 对，凡涉及 direct 的配对是 28 对。

**数字怎么算的。** 下面每个数字都来自 `.ccx/eval/r5/pg1-results.jsonl`（每单元一行，保存在跑评测的机器上，不在仓库里），用一个
不 import `scripts/eval/r5.py` 的独立脚本重算：

```bash
python scripts/research/polyglot_pg1.py .ccx/eval/r5/pg1-results.jsonl --out docs/research/data/2026-10-31-polyglot-pg1.json
```

输出（含每单元一行去掉路径的数据）在 [data/2026-10-31-polyglot-pg1.json](data/2026-10-31-polyglot-pg1.json)。干净口径的值与
`r5.py summary --taskset polyglot --tag pg1` 打印的一致。符号检验是对不一致配对做的精确双侧二项检验（McNemar 精确检验）；
bootstrap 按题重抽 29（或 30）题，2000 次，种子 31。有两样不是结果行的字段，出现处都注明了：失败分类（来自每单元的隐藏测试
输出）和核实员读运行日志得到的内容。

## 结果

| 组 | 做对，全部 30 题（Wilson 95%） | 做对，干净 | 总花费，全部 / 干净 | 每次成功，全部 / 干净 | 墙钟中位，全部 / 干净 |
|---|---|---|---|---|---|
| self | **25/30**（0.66–0.93） | 24/29 | $0.915 / $0.871 | **$0.037** / $0.036 | 11.1 秒 / 10.8 秒 |
| ccx2 | 12/30（0.25–0.58） | 12/29 | $1.381 / $1.341 | $0.115 / $0.112 | 57.4 秒 / 57.4 秒 |
| direct | 9/30（0.17–0.48） | 9/29 | $0.187 / $0.175 | $0.021 / $0.019 | 44.2 秒 / 43.9 秒 |

计划里的天花板规则（direct ≥ 27/30 就说明这组题看不出分流的作用）没有触发：direct 是 9/30。

### 配对做对数

| 配对 | 全部 30：只有 A 对 / 只有 B 对（p） | 干净：只有 A 对 / 只有 B 对（p） | 三对 Holm 校正，全部 / 干净 |
|---|---|---|---|
| self vs ccx2 | 13 / 0（p = 2.4e-4） | 12 / 0，共 29 对（p = 4.9e-4） | 4.9e-4 / 9.8e-4 |
| self vs direct | 16 / 0（p = 3.1e-5） | 14 / 0，共 28 对（p = 1.2e-4） | 9.2e-5 / 3.7e-4 |
| direct vs ccx2 | 4 / 7（p = 0.55） | 4 / 6，共 28 对（p = 0.75） | 0.55 / 0.75 |

- 两个派活组做对的题，self 全都做对，还多对 13（16）题。
- **ccx2 vs direct 不构成结论。** ccx2 多对 3 题（12 对 9），但 p = 0.55。direct 有 2 题（`pg-zebra-puzzle`、`pg-bottle-song`）
  4 秒就以 `blocked` 停下，原因没有记录。去掉这 2 题是 4 / 5（p = 1.0）；再去掉不干净的那行是 4 / 4（p = 1.0）。按计划的规则，
  不能写“分流提高正确率”。
- 28 对干净的 direct–ccx2 配对里（同一模型、同一档位），有 10 对结果相反。只跑一轮，这里大多是随机差异。

| 墙钟，逐题差值的中位数 | +46.3 秒 | +46.8 秒 |

## 为什么贵：主导侧的固定开销

字段：每个 ccx2 行的 `lead_usd`（主导自己的模型花费）和 `usd`（= `lead_usd` + `ccx_usd`，即 ccx 的工作运行和审查）；self 的
`usd` 全是主导花费。

| | 全部 30 | 干净 29 |
|---|---|---|
| ccx2：主导侧 ÷ 总花费 | 1.135 / 1.381 = **82.2%** | 1.101 / 1.341 = 82.1% |
| ccx2：主导侧，每题中位 | $0.0346 | $0.0350 |
| self：整道题，中位 | $0.0275 | $0.0274 |
| ccx2 光主导侧就比 self 整道题贵的题数 | 30 题中 24 题 | 29 题中 24 题 |
| 假如 ccx2 每单元都做对的每次成功花费（总额 ÷ 单元数） | $0.046 | $0.046 |
| self 实测每次成功 | $0.037 | $0.036 |

一道单文件练习题，主导写 brief、等待、验收的花费和自己做差不多。换更便宜或更强的子智能体都去不掉这部分：省钱只能来自自己做
本来就贵的任务。

**派活前能知道的特征都预测不了失败**（该特征对“单元失败”的 AUC，0.5 = 没有信号；特征来自 `polyglot_selection.json`；样本内
计算）：

| 特征 | ccx2 失败 | direct 失败 |
|---|---|---|
| Exercism 难度 | 0.57 | 0.54 |
| 隐藏测试数 | 0.51 | 0.38 |
| 说明长度 | 0.34 | 0.62 |

说明越长，ccx2 失败越少，direct 失败却越多：同一模型的两组连方向都不一致。diff 大小在做之前不可能知道。所以分流该用的代理量是
“预计自己做的成本”（要读和改的文件数、预计请求数），不是 diff 行数或说明长度。

## 为什么失败

**接口猜错。** 我们按隐藏测试输出的前几行报错，把 ccx2 的 18 个失败逐个归类（分类是我们做的，列在数据文件里）：

| 类别 | 数量 | 例子 |
|---|---|---|
| 接口：功能做了，但形状不是隐藏测试要的 | **14** | 该返回字符串却返回 list（`grep`）或反过来（`food-chain`）；测试传 list 却按字符串收（`forth`）；测试要返回 `False` 却抛异常（`grade-school`）；缺常量或方法（`go-counting`、`phone-number`）；报错文字不同（`tree-building`、`pov`） |
| 逻辑：行为本身错 | 4 | `bowling`、`hangman`、`connect`、`paasio` |

这些约定只在隐藏测试里，说明里没写。Codex 模型在两条路（ccx2 和 direct）上都猜错，Sonnet 主导猜对的多得多。

- **三组全错（5 题）**：`pov`、`dot-dsl`、`go-counting`、`paasio`、`tree-building`。
- **direct 对、ccx2 错（4 题）**：`bowling`、`connect`、`food-chain`、`zipper`。`zipper` 和 `food-chain` 里子智能体按自己发明的
  接口（tuple 树；一整个字符串而不是按行的 list）写了 `test_own.py`，check 在这些测试上通过，审查也放行，把错的接口锁死了。
- **ccx2 对、direct 错（7 题）**：2 题是 direct 4 秒 `blocked`（`zebra-puzzle`、`bottle-song`），1 题 direct 那行不干净
  （`scale-generator`，ccx2 这题还有一轮修复），3 题 ccx2 首次就过（`two-bucket`、`beer-song`、`sgf-parsing`：同一模型两次运行间
  的随机差异），1 题第二次尝试才过（`wordy`）。7 题里至多 2 题与返工有关。

## 审查没起作用，档位从未上升

- **check**：30 个 ccx2 单元的 `ccx_check_passed` 都是 true，其中 18 个隐藏测试失败。18 个失败全部被报成 check 通过（误报
  18/18）。check 用的是子智能体自己的测试文件。
- **升档**：所有单元的所有路由都是 `codex:gpt-6-luna:low`（`ccx_routes`）。省钱档只在 ccx 的 check 失败时升档，而子智能体自己的
  测试最后从没失败过。
- **修复轮**：ccx2 有 4 个单元有修复轮、6 个有第二次尝试（两者之一共 7 个）。其中 3 个最后做对：`wordy`（第二次尝试）、
  `scale-generator`（修复轮）、`pig-latin`（两者都有；这题每组都对）；另 4 个（`pov`、`dot-dsl`、`forth`、`react`）最后还是错。
- **审查**：每个 ccx2 单元都审查过。结果行没有记录 ccx2 的审查结论；核实员读运行日志，没有发现哪次审查指出了接口不符，但审查错
  的频率没有测量（限制 11）。direct 的行记了结论：它 19 个非 `blocked` 的失败里，18 个最后的审查结论是 `pass`。

## 限制

1. 每组 1 轮。同模型同档位的 direct 与 ccx2 在 28 对干净配对里有 10 对结果相反：运行间的随机差异很大。
2. 只有 Python。选题偏难：aider 里 7 个模型最多 3 个做对的题，再去掉最简单的 4 道。
3. 隐藏测试只给一次机会，所以不能和 aider 公布的通过率直接比。
4. 隐藏测试是 Exercism 的公开测试，模型可能见过。self 有 5 次只用 Read 和 Write（一条命令都没跑）就做对（核实员按更宽的“跑检查”
   口径数出 6 次）。这偏向记得 Exercism 约定的模型，所以“污染对各组相同”不成立。
5. 子智能体只测了 Codex gpt-6-luna low，主导只测了 Sonnet medium；没有一个单元升档。
6. ccx2 的 check 是子智能体自写的测试；18 个失败全部被报成 check 通过。
7. 主导的提示是评测脚本里写死的 `HOW_CCX2`，不是发布的技能文字；主导改写过附加说明，并加了“写 test_own.py”的目标。
8. 3 行不干净（`book-store` 的 self 和 ccx2、`scale-generator` 的 direct）只影响计时。direct 那 2 个单元为什么 4 秒就 `blocked`
   没有记录。
9. Codex 沙箱是 unelevated（pg0 预跑是 elevated）；只在 Windows 上跑；金额是 API 等价价。
10. 分流分析（AUC）是样本内算的。hc1（ccx 527982e）和 pg1（5d4bd01）版本不同，两者对比不是配对比较。
11. 审查误报的频率没有测：没有保留尝试之间的快照。可以用 `scripts/eval/fixround_replay.py` 复核。

## 对产品的含义

1. **小活留给主导自己做。** 这支持“小活自己做”，分流的代理量用“预计自己做的成本”（要读和改的文件数、预计请求数），不用 diff
   行数或说明长度。已记入 [DECISIONS](../DECISIONS.md)。
2. **子智能体自写的测试不是“check 通过”的证据。** 收据会写明通过的 check 覆盖了哪些测试文件、其中哪些是智能体写的或改的（#211，
   pg1 的 ccx 5d4bd01 里已有，但只是显示：不改变 check 是否通过）；这次运行之后，审查 rubric 把智能体自己的测试当作它自己的尺子，
   不当证据（#212，pg1 的 ccx 里没有）。升档还必须能被“自写测试全过、任务却没做对”触发：这是下一项要做的。
3. **下一步要测的**：在带 #212 的 main 上重跑 ccx2（约 $1.4），看升档这回会不会触发；这比用更强档位直接做（Codex luna medium 或
   Sonnet direct，约 $0.5–1，测档位本身的能力）更有价值。
