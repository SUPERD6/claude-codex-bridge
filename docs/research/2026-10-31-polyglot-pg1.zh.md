# 外部基准 pg1：polyglot 30 道 Python 题，自己做 vs ccx vs 直接派（2026-10-31）

[English](2026-10-31-polyglot-pg1.md) · 中文 · 回到[研究报告](README.zh.md) · [计划](2026-10-30-polyglot-slice-plan.zh.md)
（规则在运行前定好）

**polyglot 30 道 Python 题（1 轮、隐藏测试、只给一次机会）上，Sonnet 主导经 ccx 派给最便宜档做对 12/30，自己做 25/30，
每次成功贵约 3 倍、墙钟约 5 倍。不经主导直接派给同一档，每次成功比自己做便宜，但只做对 9/30。小而接口严格的题别派；
目前只在自己做较贵的仓库任务（hc1）上见到省钱，这里没有。**

三条结论（除非注明“干净”，都按全部 30 题算）：

1. **这类单文件小题，经主导派给最便宜档既错得多，每次成功又贵约 3 倍。** 这不是说 ccx 整体变差。我们的解读（不是检验过的
   结论）是它和 [hc1](2026-10-29-hc1-holdout.zh.md) 不矛盾：派活省钱要同时满足“自己做本身贵”和“子智能体一样对”两条，hc1 的
   仓库任务两条都满足，pg1 两条都不满足。hc1 和 pg1 不配对（任务不同，ccx 版本 527982e 对 5d4bd01）。
2. **即使全做对，派活也更贵：ccx2 的花费 82% 在主导侧。** 假如 30 题全对，ccx2 每次成功 $0.046，自己做实测 $0.037。光主导侧
   每题中位就是 $0.0346，自己做整道题中位 $0.0275；30 题里 24 题光主导侧就比自己做整题贵。每次成功贵 3.1 倍里约一半来自少做对
   （总花费 1.5 倍 × 成功数 25/12 ≈ 2.1 倍）。30 题全是单文件，pg1 说不出这是题的规模还是难度造成的。
3. **审查和修复轮没抓到任何接口错误，档位从未上升。** ccx2 的 check 跑的是子智能体自己写的 `test_own.py`：最终 check 30 个单元
   30 个通过，包括隐藏测试失败的全部 18 个，零区分度。审查和返工对正确率贡献多少没有测：7 个返工单元里 3 个最后做对。所有
   路由都是 Codex gpt-6-luna low。

和自己做比贵不贵，要看走哪条路：经主导派活（ccx2）每次成功是自己做的 3.1 倍；同一档不经主导直接做（direct）是 0.57 倍
（$0.021 对 $0.037；95% CI 全部 30 题 0.37–1.14，干净 28 对 0.34–0.99），代价是只做对 9/30。

## 方法

- **选题**：aider polyglot 基准（commit 7e0611e，2024-12-22）里的 30 道 Python 题，选题时不看任何解法：aider 最难的 225 题
  （2024 年 7 个模型里最多 3 个做对）中有 34 道 Python，按（Exercism 难度，测试数）去掉最低的 4 道。题单和每题理由在
  `scripts/eval/polyglot_selection.json`，任务集在 `scripts/eval/tasks_polyglot.py`。
- **单元看到什么**：一个全新的单提交仓库，只有解法桩文件（没有测试、`.meta/` 和历史），加上题目自己的说明和一段简短附加说明
  （改哪个文件、保留名字、只用标准库、测试是隐藏的）。单元里这些题没有现成测试，所以 ccx2 的 check 是子智能体自写的测试。
- **三组**，说明、隐藏测试和隔离环境都相同：

| 组 | 谁来做 |
|---|---|
| `self` | 主导 Claude Code Sonnet medium 自己做 |
| `ccx2` | 同一个主导交给 ccx（省钱档：先 Codex gpt-6-luna low，ccx 的 `--check` 失败才升一档）；练习题没有能点名的测试文件，所以主导让子智能体写 `test_own.py`，再把它当 `--check`；另一家的模型审查 |
| `direct` | 没有主导：`ccx run` 直接派给 Codex gpt-6-luna low，有审查，没有 `--check`，不升档 |

- **一轮**（tag `pg1`，运行 20261031-145737Z，ccx 固定在 5d4bd01，codex-cli 0.164.0，Claude Code 2.1.309），90 个单元，
  `--arm-order balanced`（每题三个单元连着跑）。Codex 的 Windows 沙箱是 **unelevated**（单单元预跑 pg0 是 elevated）；这个设置
  来自运行配置，结果行里没有记录。更早一次中止的尝试（沙箱凭据失效）不用。
- **评分**：题目的测试文件是隐藏的；只把解法文件复制进一个带测试的新文件夹。做对 = pytest 恰好通过该题的测试数。**只有一次机会**：
  不像 aider（两次，第二次能看到报错），评分前谁都看不到隐藏测试。
- **两种口径**都给：全部 30 题，以及只算干净行（`env_clean`，即 `r5.py summary` 的口径）。有 3 行不干净，原因是运行时看到机器上
  有别的进程（其他会话的测试和 ccx 运行）：

| 干净口径排除的行 | 做对 | 排除原因 |
|---|---|---|
| `pg-book-store` self | 对 | 单元运行时看到别的进程 |
| `pg-book-store` ccx2 | 错 | 单元运行时看到别的进程 |
| `pg-scale-generator` direct | 错 | 单元运行时看到别的进程 |

所以干净口径每组 29 个单元，self–ccx2 有 29 对，凡涉及 direct 的配对是 28 对。

**数字怎么算的。** 下面每个数字都来自 `.ccx/eval/r5/pg1-results.jsonl`（每单元一行，保存在跑评测的机器上，不在仓库里），用一个
不 import `scripts/eval/r5.py` 的独立脚本重算：

```bash
python scripts/research/polyglot_pg1.py .ccx/eval/r5/pg1-results.jsonl --out docs/research/data/2026-10-31-polyglot-pg1.json
```

输出（含每单元一行去掉路径的数据）在 [data/2026-10-31-polyglot-pg1.json](data/2026-10-31-polyglot-pg1.json)；跑两次逐字节一致。
干净口径的值与 `r5.py summary --taskset polyglot --tag pg1` 打印的一致。符号检验是对不一致配对做的精确双侧二项检验（McNemar
精确检验）。成本 bootstrap 按题重抽 29（或 30）题，2000 次，种子 31；AUC bootstrap 按题重抽 4000 次，种子 7；两者都是不插值的
百分位区间（取排序后第 ⌊q·(n−1)⌋ 个值）。墙钟按四舍五入（half up）到 0.1 秒。有三样不是结果行的字段，出现处都注明了：失败分类
（来自每单元的隐藏测试输出）、核实员读运行日志得到的内容、对最终 diff 的 grep。**核实员**指写报告之前独立复核这次运行的数字和
日志的两位审查员。

**作弊检查。** 搜了全部 90 个 `final.diff`（保存在跑评测的机器上）：没有一个碰 `sys.modules`、`builtins`、`conftest.py`、
`monkeypatch` 或 `importlib`（唯一一处 `builtins` 是 `forth.py` 里 Forth 内置词的局部集合）。self 和 direct 只改了解法文件；ccx2
另外加了 `test_own.py` 和 `brief.md`，里面 pytest 只是正常用法（`import pytest`、`pytest.raises`、`parametrize`）。

  4 秒就以 `blocked` 停下，原因没有记录。去掉这 2 题是 4 / 5（p = 1.0）；再去掉不干净的那行是 4 / 4（p = 1.0）。按计划的规则，

- 28 对干净的 direct–ccx2 配对里有 10 对结果相反（去掉 direct 的 2 个 `blocked` 是 26 对里 8 对）。两组模型和档位相同，但条件
  不同（ccx2 有主导写的 brief、自写 check 和修复轮），不能当纯随机误差。

## ccx2 为什么贵：主导侧

字段：每个 ccx2 行的 `lead_usd` 和 `usd`（= `lead_usd` + `ccx_usd`）；self 的 `usd` 全是主导花费。`lead_usd` 是单元里主导的全部
Claude 花费，包括写 brief、等待的那一轮和验收；7 个返工单元更高（中位 $0.048，其余 23 个 $0.034）。审查费计在 `ccx_usd`，
不在这里。

| | 全部 30 | 干净 29 |
|---|---|---|
| ccx2：主导侧 ÷ 总花费 | 1.135 / 1.381 = **82.2%** | 1.101 / 1.341 = 82.1% |
| ccx2：主导侧，每题中位 | $0.0346 | $0.0350 |
| self：整道题，中位 | $0.0275 | $0.0274 |
| ccx2 光主导侧就比 self 整道题贵的题数 | 30 题中 24 题 | 29 题中 24 题 |
| 假如 ccx2 每单元都做对的每次成功花费（总额 ÷ 单元数） | $0.046 | $0.046 |
| self 实测每次成功 | $0.037 | $0.036 |

一道单文件练习题，主导侧（包括写 brief、等待和验收）的花费和自己做差不多。换更便宜或更强的子智能体都去不掉这部分。

**事后探索：试过的特征都看不出预测力。** 计划里没有这项分析。各特征对“单元失败”的 AUC（0.5 = 没有信号；特征来自
`polyglot_selection.json`；样本内；按题 bootstrap 95% CI，4000 次，种子 7），ccx2 失败 18 个、direct 失败 21 个：

| 特征 | ccx2 失败 | direct 失败 |
|---|---|---|
| Exercism 难度 | 0.57（0.35–0.77） | 0.54（0.32–0.76） |
| 隐藏测试数 | 0.51（0.28–0.74） | 0.38（0.16–0.61） |
| 说明长度 | 0.34（0.14–0.56） | 0.62（0.37–0.84） |

六个区间全都包含 0.5：在 18 和 21 个失败样本上，试过的 3 个特征看不出预测力。diff 大小在做之前不可能知道。用“预计自己做的
成本”（要读和改的文件数、预计请求数）当分流代理量，是由上面 82% 推出的假设；pg1 每题都是单文件，无法检验。一条对它有利的弱
观察（样本内、事后）：ccx2 比 self 便宜的 3 题（`paasio`、`book-store`、`sgf-parsing`）都在 self 成本偏高端（30 题里排第 26、
28、30）。

## 为什么失败

**接口猜错。** 我们中的一人按隐藏测试输出的前几行报错，把 ccx2 的 18 个失败逐个归类。这是单人编码，没做一致性检验，原始的
hidden-pytest 输出不在仓库里（分类和每单元一句理由在数据文件里）：

| 类别 | 数量 | 例子 |
|---|---|---|
| 接口：功能做了，但形状不是隐藏测试要的 | **14** | 该返回字符串却返回 list（`grep`）或反过来（`food-chain`）；测试传 list 却按字符串收（`forth`）；测试要返回 `False` 却抛异常（`grade-school`）；缺常量或方法（`go-counting`、`phone-number`）；报错文字不同（`tree-building`、`pov`） |
| 逻辑：行为本身错 | 4 | `bowling`、`hangman`、`connect`、`paasio` |

说明只提示要匹配隐藏测试（保留名字），没给具体形状或报错文字。Codex 模型在两条路（ccx2 和 direct）上都猜错，Sonnet 主导做对的
多得多（可能部分来自记得 Exercism 约定，见限制 4）。

- **三组全错（5 题）**：`pov`、`dot-dsl`、`go-counting`、`paasio`、`tree-building`。
- **direct 对、ccx2 错（4 题）**：`bowling`、`connect`、`food-chain`、`zipper`。`zipper` 和 `food-chain` 里子智能体按自己发明的
  接口（tuple 树；一整个字符串而不是按行的 list）写了 `test_own.py`，check 在这些测试上通过，审查也放行，把错的接口锁死了。
- **ccx2 对、direct 错（7 题）**：2 题是 direct 4 秒 `blocked`（`zebra-puzzle`、`bottle-song`），1 题 direct 那行不干净
  （`scale-generator`，ccx2 这题还有一轮修复），3 题 ccx2 首次就过（`two-bucket`、`beer-song`、`sgf-parsing`），1 题第二次尝试
  才过（`wordy`）。7 题里至多 2 题与返工有关。

## 审查和修复轮没抓到任何接口错误；check 零区分度；档位从未上升

- **check**：30 个 ccx2 单元的 `ccx_check_passed`（最终 check）都是 true，其中 18 个隐藏测试失败，所以每个失败都被报成 check
  通过（18/18），check 什么都没区分开。check 用的是子智能体自己的测试文件。有 3 个单元（`wordy`、`react`、`pig-latin`）第一次
  尝试的 check 失败，ccx 在同一档重试；为什么重试而不是升档，这里没有查。
- **升档**：所有单元的所有路由都是 `codex:gpt-6-luna:low`（`ccx_routes`）。省钱档在 ccx 的 check 失败时升档，而子智能体自己的
  测试最后都通过了。
- **修复轮和第二次尝试**：ccx2 有 4 个单元有修复轮、6 个有第二次尝试（两者之一共 7 个）。第二次尝试有两种来源：3 个是主导用
  `ccx resume` 打回（`pov`、`dot-dsl`、`forth`），3 个是 ccx 自己的 check 失败后重试（`wordy`、`react`、`pig-latin`）。7 个里
  3 个最后做对：`wordy`（第二次尝试）、`scale-generator`（修复轮）、`pig-latin`（两者都有；这题每组都对）；另 4 个（`pov`、
  `dot-dsl`、`forth`、`react`）最后还是错。`wordy` 和 `scale-generator` 上 direct 也错，但 `scale-generator` 的 direct 行不干净；
  返工对正确率贡献多少没有测。
- **审查**：每个 ccx2 单元都审查过。结果行没有记录 ccx2 的审查结论；核实员读运行日志，没有发现哪次审查指出了接口不符，但审查错
  的频率没有测量（限制 11）。direct 的行记了结论：它 19 个非 `blocked` 的失败里，18 个最后的审查结论是 `pass`。

## 限制

1. 每组 1 轮。direct 与 ccx2 在 28 对干净配对里有 10 对结果相反（去掉 direct 的 `blocked` 是 26 对里 8 对）；两组条件不同（brief、
   自写 check、修复轮），这不能当纯随机误差的量度，一轮的波动有多大不知道。
2. 只有 Python。选题偏难：aider 里 7 个模型最多 3 个做对的题，再去掉最简单的 4 道。30 题全是单文件。
3. 隐藏测试只给一次机会，所以不能和 aider 公布的通过率直接比。
4. 隐藏测试是 Exercism 的公开测试，模型可能见过。self 有 5 次只用 Read 和 Write（一次 Bash 都没调）就做对；核实员按更严的
   “跑检查”口径数出 6 次（只写文件的 Bash 不算跑检查）。这偏向记得 Exercism 约定的模型，所以“污染对各组相同”不成立。
5. 子智能体只测了 Codex gpt-6-luna low，主导只测了 Sonnet medium；没有一个单元升档。
6. ccx2 的 check 是子智能体自写的测试；18 个失败全部被报成 check 通过。
7. 主导的提示是评测脚本里写死的 `HOW_CCX2`，不是发布的技能文字；主导改写过附加说明，并加了“写 test_own.py”的目标。
8. 3 行不干净（`book-store` 的 self 和 ccx2、`scale-generator` 的 direct），两种口径处处都给。direct 那 2 个单元为什么 4 秒就
   `blocked` 没有记录。
9. Codex 沙箱是 unelevated（pg0 预跑是 elevated）；只在 Windows 上跑；金额是 API 等价价。
10. 分流分析（AUC）是事后、样本内算的。hc1（ccx 527982e）和 pg1（5d4bd01）版本不同、任务不同，两者对比不是配对比较。
11. 审查误报的频率没有测：没有保留尝试之间的快照。可以用 `scripts/eval/fixround_replay.py` 复核。
12. 失败分类是一个人做的，没做一致性检验；原始隐藏测试输出和最终 diff 不在仓库里。

1. **方向，尚未实现：小活留给主导自己做。** pg1 支持“小活自己做”，但 `config/tiers.toml [routing] small_self` 出厂仍是关：hc1
   上 ≤ 1 个文件的活自己做成本 +5%，方向和 pg1 相反，这个开关等 P0-6 实测再定。分流代理量可以是“预计自己做的成本”（假设，见上），
   不是 diff 行数或说明长度。现有的分档规则（DECISIONS 2026-10-26）把简报 ≥ 180 词的任务判为大任务，balanced 会把大任务交给
   ccx2；按最终 diff 里 `brief.md` 的空白分词粗数，pg1 的 30 份 ccx2 简报有 27 份 ≥ 180 词，而每道题都只有一个文件。已作为方向记入
   [DECISIONS](../DECISIONS.md)。
2. **子智能体自写的测试不是“check 通过”的证据。** 收据会写明通过的 check 覆盖了哪些测试文件、其中哪些是智能体写的或改的（#211，
   pg1 的 ccx 5d4bd01 里已有，但只是显示：不改变 check 是否通过）；这次运行之后，审查 rubric 把智能体自己的测试当作它自己的尺子，
   不当证据（#212，在 `ccx/review.py`，pg1 的 ccx 里没有）。这条规则目前只在 #212 的审查 rubric 里生效：check 和升档都不用它。
3. **下一步要测的**：先让升档能被“自写测试全过、任务却没做对”触发，再重跑 ccx2（约 $1.4）。在今天的 main 上直接重跑测不到升档
   （只在 check 失败时升档，而 check 仍跑 `test_own.py`）；它能测的是 #212 的审查能否抓到接口不符、开出修复轮。两者都比用更强
   档位直接做（Codex luna medium 或 Sonnet direct，约 $0.5–1，测档位本身的能力）更有价值。
