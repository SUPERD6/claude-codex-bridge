# Round 5: large tasks (this repository's own real changes): does delegating save, is it more right? (plan)

English · [中文](2026-10-26-r5-plan.zh.md) · 2026-10-26 · written before the formal runs (changes after the one-task pilot are in §7)

Earlier: [round 3](2026-10-25-r3.md), [round 4](2026-10-26-r4.md). Round 4: on small tasks cheap models are right on
the raw request, and a lead makes 4–7 requests whether it does the work or hands it away, so delegating does not
save. ccx can only save the lead's money when the work handed away itself takes many requests. This round tests that.

## 1. Tasks (`scripts/eval/tasks_r5.py`, 10)

All are real merged changes of this repository. Each task is the **whole repository** at the parent of that commit
(~19k lines of ccx code, ~300 files). The brief is written like an issue: what is wrong or missing, then the interface
the maintainers' tests use (function names, return shapes, text that must appear as is), never how to implement it.
**The hidden test is that commit's own test files.**

| id | from | what to do |
|---|---|---|
| brief-words | #116 | picking notes for a brief ignores trailing punctuation and common words; `recap` at the end of `ccx run` output |
| q-killed-spend | #104 | after a killed `q run`, close runs stuck in running as interrupted, spend into the ledger and the item |
| q-resume-session | #105 | `q resume` continues the killed run's session; finished pieces are not redone |
| batch-review-risk | #100 | `ccx batch` plan `review` / `risk` reach the run |
| codex-hook-text | #92 | hook output for Codex does not start with `[` / `{` |
| projects-refresh | #90 | rescan a stale project catalog in the background at session start, one scan at a time |
| dsh-archive | #89 | archive dsh sessions by adding the id to the desktop app's archived list; restore and resume take it out |
| quota-stop-log | #62 | every quota stop writes its evidence to `quota-stops.jsonl`; `ccx quota` shows the last five |
| waiting-evals | #59 | the start-up "waiting for you" count leaves out evaluation runs |
| mem-report | #52 | record who used shared notes; `ccx mem report` |

**Screening**: of 32 commits that changed code and added tests, 29 had tests that fail on the parent and pass with
the commit's code; Windows-only timing fixes, tasks whose tests assert too many exact strings to brief fairly, and
overlapping tasks were dropped, leaving 10. The evaluation script checked again: all 10 fail at the start and pass
with the reference.

**Test isolation**: tests before #73 may not give every test its own hub. Each task repository starts with today's
`tests/conftest.py` committed (own hub, tool homes and config per test), and scoring points `HOME`, `CCX_HUB`,
`CODEX_HOME` and `CLAUDE_CONFIG_DIR` at throwaway folders, so the machine's real hub and tool configs are never touched.

**Contamination**: the repository went public in 2026-10, after the models' training cut-off.

## 2. Four arms

The lead is always a fresh headless Claude Code (sonnet, effort medium, slim start, as round 3); only the route differs:

| Arm | What happens |
|---|---|
| self | the lead does it itself |
| builtin | the lead may not edit; hands it to a haiku `worker` with the Agent tool, checks, sends it back if wrong |
| ccx | the lead may not edit; hands it to `ccx run --tradeoff save --review on --context auto` (its own `--check` with the relevant tests), checks, `ccx resume` if wrong |
| direct | no lead: `ccx run` straight to Codex gpt-6-luna low with review on (the cheapest reviewer from another vendor), no `--check` (giving one would tell it which file the hidden test is in) |

Later, opt-in arms (not in the default schedule; each is described at the top of `scripts/eval/r5.py`): `ccx2`
(ccx as the agent-delegate skill teaches it), `ccx2-skill`, `builtin2`, `builtin2r`, the tier arms `fast`, `balanced`,
`save`, `cheapest`, and, for iteration test r6a, **`ccx2nc`**: exactly `ccx2`, except that the unit's own hub sets
`[defaults] namecheck = "fail"` in its tiers.toml (checked from the hub before the lead starts), so a sub-agent change
that uses an undefined name fails its run like a failed `--check`; ccx's own default stays `warn`. Every row records
the hub's mode (`namecheck_mode`) and each builder run's own (`ccx_namecheck`), and the summary counts them per arm
(`namecheck`). An `--arms` entry `<arm>@auto` is that arm with its lead model picked per task (`--lead-model auto` for
those units only, arm `ccx2@auto-medium`), so r6a's three arms interleave in one invocation:
`python scripts/eval/r5.py run --rounds 1 --arms ccx2,ccx2nc,ccx2@auto --tag r6a --budget 10`.

The lead is told that the full suite takes ~7 minutes and to run the relevant tests. Each unit gets a fresh repo and a
fresh throwaway hub (as round 3: Codex held to luna low, routing without sonnet/opus/fable, A/B off, DeepSeek uncapped
but counted). Every run carries `--no-ab` and an `eval-r5:` label.

## 3. Measures and verdicts (fixed beforehand)

- **Right**: every hidden test passes.
- **Cost per success (CPS)**, as round 3: the lead's and the built-in sub-agent's `total_cost_usd` from `claude -p`,
  ccx's API-equivalent dollars from the ledger.
- **Lead spend, lead tokens, lead requests, wall time, rework**, as round 3.
- **Statistics**: the task is the unit; 10 tasks × 2 rounds. Correctness by paired exact McNemar (a pair = same task,
  same round). Primary test **ccx vs self**; secondary ccx vs builtin, direct vs self, builtin vs self; Holm over the 4.
  Spend, lead spend and time by task-level paired differences: median, bootstrap interval and sign test, descriptive.
- **Verdicts**:
  - "ccx is cheaper than the lead doing it": ccx's total spend (lead + sub-agent + review) is below self's, the
    task-level paired interval excludes 0 and the sign test p < 0.05. The lead's own share is reported to explain why.
  - "ccx is more right": Holm-adjusted p < 0.05 in its favour.
  - "a cheap model alone is enough": direct is right on no more than 2 tasks fewer than self, at under half its CPS.
  - Otherwise only direction and intervals are reported. With 10 tasks a correctness gap must be large (about 6 : 0
    discordant) to be significant; said beforehand.

## 7. Changes after running

- **10/26, after the quota-stop-log pilot of all four arms** (formal data; that task's round 1 is not run again): self
  was wrong (1 hidden test failed) after 18 lead requests, $0.270; builtin right, 10 requests, $0.270; ccx right,
  8 requests, $0.226 (lead $0.184), one `ccx resume`; direct right, $0.037. About $0.80 and 16 minutes per task for
  the four arms.
- **Estimate**: 19 task × round left, about $15 at the pilot's prices; tasks differ in size and a lead may spend up to
  $3, so with a 1.5–2× margin **$20–30**, budget cap **$30**. Two tasks at a time (`--jobs 2`): about 3 hours.
- The leads committed their work (AGENTS.md says so) and the script only counted uncommitted changes, showing 0 files.
  It now compares with the start commit (`changed()`); the pilot's 4 rows were recounted that way (they include the
  hidden test files written at scoring; formal runs count before scoring).
- Added `--jobs`: a task's four arms run one after another in their shuffled order, up to N tasks at a time.

## 8. Clean environment (after r5h; `scripts/eval/preflight.py`)

An audit of the r5-r5g logs found that every lead (and many ccx Claude sub-agents) had loaded the person's user-level
settings: their SessionStart / UserPromptSubmit hooks (one injected private rule text, two ran the main checkout's
`ccx.py`), the user CLAUDE.md, auto-memory in the real `~/.claude`, and the `language` setting. Codex sub-agents used
the real CODEX_HOME (its AGENTS.md, config with plugins / MCP / hooks / memories, rules). Sessions, tool-result files
and Codex trust entries were written into the real homes; timeouts killed only the direct child. From now on:

| | What it does |
|---|---|
| E1 from zero | Allow-listed environment; per unit its own TMP, git identity, CCX_CONFIG, DSH_HOME. Claude lead and ccx Claude sub-agents: `--setting-sources project,local`, a settings file with `disableAllHooks`, auto-memory off, `claudeMdExcludes` for the user CLAUDE.md / rules and deny rules for the real `~/.claude` files, `~/.codex`, `~/.ccx`, the real hub and the eval checkout (sub-agents via the opt-in `CCX_CLAUDE_SETTING_SOURCES` / `CCX_CLAUDE_SETTINGS`). `--claude-isolation config-dir`: a fresh CLAUDE_CONFIG_DIR per unit (needs `CLAUDE_CODE_OAUTH_TOKEN`). Codex: a dedicated eval CODEX_HOME the person logged in to (`--codex-home`), and `CCX_CODEX_ISOLATE=1` (`--ignore-user-config --ignore-rules`, memories off). |
| E2 no leftovers | Each unit's processes run in a Job Object; survivors and new processes naming the unit are listed (with ports), killed and logged in one line. The unit's x- folder, its worktrees and (flags mode) its Claude session folders are removed. |
| E3 same inputs | Fingerprint per row: commit, task-file hash, `claude` / `codex` / `dsh --version` (re-checked after every unit), eval CODEX_HOME file names and models_cache hash, isolation mode, empty shared memory. |
| E4 no interference | Refuses to start while another eval, pytest or `ccx run` runs outside this run; concurrency recorded; re-checked between units. |
| E5 preflight | Any problem blocks the run; `--force-unclean` runs anyway and is recorded. A canary lead (one haiku request) must see only the project's CLAUDE.md -> AGENTS.md. Each row gets `audit` (init event: no hooks, MCP, skills, non-builtin plugins, outside memory; no tool call naming a real home, hub or the checkout) and `env_clean`. |

Not blocked by mechanism, recorded instead: Bash can still read any file the user can (no Claude sandbox on
Windows), so the per-row audit is the check; in flags mode Claude still writes `~/.claude.json` project entries; the
eval CODEX_HOME is shared by the units of one run (memories off, distinct working directories). Not yet verified by a
real run: that `--setting-sources` plus `claudeMdExcludes` drops the user CLAUDE.md (the canary checks it before every
run), the Windows form of the `//` deny-rule paths, and dsh with an empty DSH_HOME.

**After two independent reviews (same day).** Fixed: deny rules now use the form Claude Code matches on Windows
(`//c/Users/...`, permissions docs) and the canary checks them by trying to Read a folder its own rules deny; the
audit understands `~`, `$HOME`, `%USERPROFILE%`, `$env:USERPROFILE` and Git Bash's `/c/...`, and matches whole path
components (a sibling unit `1-t-ccx2` is no longer allowed by `1-t-ccx`); the deny list covers every project's memory
and transcripts, file history, sessions, settings backups and `~/.agents`; Codex and dsh get a home of their own
(`CCX_AGENT_HOME`), because codex-cli 0.164.0 loads user skills from `$HOME/.agents/skills`; ccx Claude sub-agents
run without skills / slash commands / MCP (`CCX_CLAUDE_NO_SKILLS`); checking alone changes nothing on disk, and a
starting run never cleans a work dir another process names or while the machine is busy; the model list is hashed
without `fetched_at` / `etag` and Codex's own `skills/.system` is allowed; the real hub default is `~/.ccx-hub`; a
Codex home overlapping a real home is refused; job processes are killed by closing the job (no pid reuse), ports
are read before; children start suspended until they are in the job; between units the commit, task file and
versions are re-checked and a watcher samples the machine every minute (`codex exec`, `claude -p` and an installed
`ccx run` count as heavy, shells and the desktop apps do not); rows carry models, python / pytest / OS and the
`tiers.toml` hash, also when the unit broke; `env_clean` is false when processes could not be listed or the machine
changed; an unkillable process stops the run; a changed own state after the run exits 4; `summary --tag` keeps
rounds apart. Still not blockable: shell reads (Claude Bash, Codex / dsh shell) of any file the user can read, a
Codex command run as another user by its Windows sandbox, `~/.claude.json` entries and shell snapshots in flags mode.
