# 热车道：小活续在热会话里，比每块开新会话省多少（报告）

[English](2026-10-25-warm-lanes.md) · 中文

2026-10-25 · `ccx batch --lanes N`（`ccx/lanes.py`）· 脚本 `scripts/eval/warm_lanes.py` · 实测花费 $0.25

## 先说结论

| 问题 | 结果 |
|---|---|
| 续跑的块能少读多少 | 未缓存输入从每块约 2.1 万降到 2 千–5 千（少 80–90%），缓存读取照旧约 8–11 万 |
| 省钱吗 | **比每块一个新会话省约 40%**（子智能体花费中位数 $0.020 对 $0.032），但**仍是一个运行做完 10 块的 4–5 倍**（$0.004） |
| 省 token 吗 | **按 token 数不省**：总数 94–121 万，和 10 路并行（99–116 万）差不多。Codex 每次请求都把系统提示和工具定义从缓存里重读一遍，续跑只省掉了新读的那部分 |
| 快吗 | **更慢**：2 条车道 97–101 秒、3 条 82–93 秒；10 路并行 28–43 秒；一个运行做完 10 块 69–100 秒。块是一块接一块做的，续跑的块本身快约 25%（13–16 秒对 18–25 秒） |
| 做对没有 | 四组 × 2 轮都是 10/10，没有合并冲突 |
| 默认 | 保持关闭（`[lanes] default = 0`）。2026-11-01 H11 试用结束后由统筹决定；按这次数据**不建议默认打开** |

## 1. 怎么测的

任务就是第 2 轮的 PAR10：10 个互不相关的小模块，每个要写函数和测试，隐藏测试判对错
（`scripts/eval/tasks_r2.py`）。Codex 只用 `gpt-6-luna` low；每个单元一个临时 hub（`CCX_HUB`），
A/B 自做关闭；验收 `python -m pytest -q`，`--review` 用默认 auto。每组 2 轮（n = 2）。

| 组 | 做法 |
|---|---|
| p1 | 一个 `ccx run` 拿到全部 10 块的说明，一次做完（`--no-subagents`） |
| p10 | `ccx batch`，10 块各一个运行同时跑，各自 worktree |
| l2 / l3 | `ccx batch --lanes 2/3`，10 块各一个运行，分成 2/3 条车道；车道第一块开会话，后面的块续进同一会话（每块单独 `--check`、单独记账，worktree 里每块一个提交），车道之间并行 |

l2 第 1 轮用的是旧上限（按车道累计 40 万 token 切会话，到 4–5 块就切）；看了数据后改成按单块计
（20 万），第 2 轮和 l3 都是新上限。两种上限下都是 5 块左右换一次会话，结果差不多。

## 3. 这说明什么

- **9.3 万“启动开销”大部分不在会话里，而在每次请求里。** Codex 每个请求都带着系统提示、工具定义和整段历史，
  只是大部分走缓存。续跑把每块的新读从 2 万压到几千，钱减半；但 token 数基本不变，会话越长每块重读越多。
- **真正省的办法是少开运行，而不是续会话。** 一个运行做完 10 块（p1）的花费是热车道的 1/5，还更快。热车道
  只在块**必须**是分开的运行时有用：每块要自己的 `--check`、自己的 undo、自己的对错记录，或者块是陆续进队列的。
  这时它比每块一个新会话省约 40%，代价是车道内按顺序做，变慢。
- 按“token 数”定上限会被便宜的缓存读取主导，所以上限改成单块（`max_tokens` = 某一块用的 token），外加
  `max_blocks`（5）。

## 4. 建议

1. 默认保持关闭；试用结束后也不建议默认打开。
2. 对“很多块很小”的情况，统筹（`project-manager`、`task-split`）应先把能合并的块**合进一个说明**交给一个运行
   （p1，或第 2 轮的 p3），而不是开很多运行；`--lanes` 留给每块要单独验收 / 撤回的情况。
3. 后续可以考虑第三种做法：车道里不续会话，而是把同一车道的块合成一个说明、一个运行，ccx 再按块分别跑 `--check`。
   这次没做也没测。

## 5. 没验证的

- n = 2，只做了描述性比较，没做统计检验；都是同一种 10 块小模块的活。
- 只测了 Codex luna low；Claude（缓存按 5 分钟 / 1 小时计、写缓存要收费）和 DeepSeek 的续跑省多少没测。
- `ccx q run --lanes` 只有假 CLI 测试，没有真机跑。
- 失败后换新会话、超上限换新会话在真机上只看到了 `max_blocks` 触发；失败换新只有假 CLI 测试。
- 每块一个提交在真机上看到了（三条车道分支都无冲突合并回去）；用 `git revert` 撤回某一块没在真机试。
