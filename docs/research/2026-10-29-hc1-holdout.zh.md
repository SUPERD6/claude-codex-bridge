## 一段话的结论

**按预登记的规则，“同等正确率下更省”成立，有限定。** 在 10 个做 ccx 时没用过的任务上（3 轮，计入 90 个单元），三组正确率
没有可分辨的差别：ccx2 29/30、主导自己做 29/30、Claude Code 自带子智能体的默认用法 27/28（按任务的差值区间约 ±3/30）。
ccx2 每次成功 **$0.063**，比自己做（$0.090）低约 **30 %**，比自带子智能体默认用法（$0.103）低约 **39 %**，两个配对差的 95 %
区间都不含 0。代价是速度：ccx2 墙钟中位 61 秒，约为**自己做的 3 倍**（21 秒）；比自带子智能体（123 秒）快。墙钟按预登记只报告。
外部仓库的 5 个任务（干净的那一半，见限制 2）上节省约 **15 % / 42 %**。这里的自带子智能体是默认用法、做法更重；精简做法的
builtin2 不在这次运行里，开发集上它比 ccx 便宜（限制 1）。

建议对外措辞（不要去掉限定）：

> 在 10 个留出任务上，经 ccx 把实现交给 Codex，与主导自己做、Claude Code 自带子智能体的默认用法相比，未见正确率更差
> （29/30、29/30、27/28），每次成功花费低约 30% / 39%；墙钟约为自己做的 3 倍。外部仓库的 5 个任务上节省约 15% / 42%。

## 3. 按预登记规则判定

- **非劣（预登记的逐点规则）**：ccx2 29 ≥ 29 − 2 → **满足**。这不是统计意义上的非劣检验：按任务的差值区间约 ±3/30，
  数据排除不了“差 2 个以上”。所以只说“未见更差”，不说“一样准”。

## 7. 有效性与限制（必须和数字一起说）

1. **builtin 是默认用法**：builtin 的主导被要求读 diff、跑测试，haiku worker 的提示要它跑全量 `python -m pytest -q`；ccx2 用定向
   `--check`，并被告知检查通过就直接接受。差价里有一部分来自指令不同，而不是 ccx 本身。开发集上给自带子智能体同样精简做法的
   builtin2（r5d）为 17/20、$0.114/成功；r5h 的 ccx2 为 19/20、$0.135/成功（不同轮次、非配对、开发集，r5h 还有 CPU 干扰）。
   本次没有 builtin2 组，只能说“比自带子智能体的默认用法便宜”。
2. **本仓库任务可能泄漏答案**：本仓库 5 个任务的参考答案就在 ccx2 所运行的那份 ccx 代码里（b473976 晚于这些改动），
   Codex 的 shell 读取不受限，审计看不到；而对 self 的节省大部分来自这些任务。外部仓库 5 个任务没有这个问题，那里的节省
   是 −15%（对 self）/ −42%（对 builtin）。
3. **外部提交可能被模型记住**：外部任务的提交日期 2018-10 到 2026-09，早于模型训练截止的可能被记住，三组同样受影响。
4. **样本小**：10 个任务，3 轮不独立；按任务的区间才是该看的。
5. **只测了 Sonnet medium 主导**；Codex 起步 gpt-6-luna low（save 档，失败可升档），每次运行实际用的模型没记在结果行里。
6. **金额是 API 等价价**（按价目表折算），Codex 实际走订阅。
7. **编排层审计没有数据**：它要读每个单元的 hub，单元结束后 hub 已清理，0 个单元可审。时间线（`r5_timeline`）可用。
8. postflight 记到一处“主人状态”变化：本工作目录对应的 Claude 项目文件夹 1 → 0（之前作废运行留下、本次清理）；账本字节不变。
