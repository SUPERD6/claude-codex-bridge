# Round 4: where do cheap models fail, and does delegating save in a long lead session? (report)

English · [中文](2026-10-26-r4.zh.md) · 2026-10-26 · ccx 0.5.0+ (after main `d2ab155`, with #118/#119) · claude 2.1.309 · codex-cli 0.164.0 · Windows 11

Script: `scripts/eval/r4.py` (tasks reused from `tasks_r3.py` and round 2's COMPOUND in `tasks_r2.py`). Scrubbed data:
[data/2026-10-26-r4.json](data/2026-10-26-r4.json). No separate plan was written beforehand: the design is in the script's
docstring, and what changed after running is in §4.

## Conclusions first

| Question | Verdict | Evidence |
|---|---|---|
| Given the person's raw request (no lead), do cheap models fail? | **Hardly; ceiling again** | 15 tasks × 2 rounds: deepseek-flash 30/30, haiku 30/30, luna 26/30, sonnet 30/30. luna failed only debug-line and inventory (0/2 each) |
| Does another vendor's review rescue luna? | **All 4 rescued, too few to be significant** | luna alone 26/30 → with review 30/30 (discordant 4 : 0, McNemar p = 0.125); about $0.006 more per task |
| Cheap models vs sonnet | **Same correctness at ~1/10 of the spend** | 30 tasks: flash $0.15, haiku $0.15, luna + review $0.25, sonnet $1.44 |
| In a long lead session (~110k tokens of history), does delegating save? | **No; doing it yourself is cheapest** | 5 tasks once each, all three arms 5/5. Cost per success: self $0.567, ccx $0.595, built-in $0.613; self → ccx paired +$0.033 [−0.028, +0.072], p = 0.375 |
| Why not | **The lead makes as many requests either way** | Every lead request re-reads the whole history (~115k tokens, cached). Self 4–7 requests; delegating 5–7 (write a brief, run ccx, read the diff, run the tests); the sub-agent side costs ~$0.01 |

**Total spend about $14.2**: calibration $2.08; long sessions $12.12 (two seed sessions $0.95 and a dropped pilot of
about $2.3, see §4).

**In one line**: on small tasks cheap models get the raw request right almost every time, so "ccx makes cheap models
more right" cannot show; and a lead doing a small task itself needs 4–7 requests, which delegating does not reduce, so
it does not save in a long session either. ccx can only save lead tokens when the work handed away would take the lead
many requests (large tasks, edit-run-debug loops). This round did not have such tasks.

## 2. Long lead session

- **Seed**: a sonnet lead first reads all 17 project notes (`docs/research/*.md` in English plus DESIGN and DECISIONS,
  ~213k characters) and summarizes them: ~110k tokens of context. Each unit continues from that history with
  `claude -p --resume <seed> --fork-session` on a new task, in a fixed repo path (sessions belong to a path). The
  built-in arm forks its own seed started with the same `--agents` flags (§4).
- Arms as in round 3: do it yourself / must hand it to a haiku `worker` / must hand it to
  `ccx run --tradeoff save --review on --context auto`.
- 5 tasks (coupon, csv-report, debug-line, rename-user, search-api), once each.

| Metric | self | built-in | ccx |
|---|---|---|---|
| Right | 5/5 | 5/5 | 5/5 |
| Cost per success | **$0.567** | $0.613 | $0.595 |
| Lead tokens, median | 575k | 708k | 580k |
| Lead requests | 4–7 | 5–6 | 5–7 |
| Wall time, median | **19 s** | 44 s | 75 s |
| Delegated | — | 5/5 | 5/5 (on debug-line the lead passed the brief in a `$BRIEF` variable, which the script's count missed; it also ran `ccx resume` once) |

Paired differences (5 tasks; the smallest sign-test p is 0.0625, so nothing can be significant): self → ccx +$0.033
[−0.028, +0.072]; built-in → ccx −$0.025 [−0.046, +0.036]; self → built-in +$0.048 [+0.018, +0.070]. ccx was the
slowest every time (+57 s vs self).

**Reading it**: every lead request re-reads ~115k tokens at the cache price, so the lead's spend ≈ requests × that
re-read. Delegating swaps "edit, run the tests" requests for "write a brief, run ccx, read the diff, run the tests"
requests: about as many, so about the same spend; the sub-agent and review cost $0.007–0.013. Round 3's "ccx −25 %
lead tokens" did not appear in the long session (580k vs 575k).

## 3. What this means

1. **Small tasks should be done by the lead itself**, or go to a cheap model from the start (no expensive lead): cheap
   models are 26–30/30 right on the raw request at about 1/10 of sonnet's spend.
2. **ccx saves lead tokens only when the work handed away itself takes many requests**: large tasks with
   edit-run-debug loops, or a long read-only investigation. That is what the next round must test, not vaguer small
   tasks.
3. **Review helps, evidence still weak**: all 4 luna failures rescued, 4 : 0; more failing tasks are needed.
4. The current task sets (rounds 1–3) no longer separate strong from weak: move to larger tasks (many files, many test
   runs, real-repository issues).

## 4. Changes after running (in order)

- **First long-session pilot: the built-in arm missed the prompt cache entirely.** All three arms first forked one seed
  started with only Read/Grep/Glob. The self and ccx arms read ~109k cached tokens on their first request; the built-in
  arm's `--agents` and Agent tool changed the start of the prompt, so its first request rewrote 115k tokens of cache,
  ~$1.0 a unit. A real long session with the Agent tool keeps it warm, so this was an artefact of the evaluation. The
  built-in arm now forks its own seed (same flags, same reading instruction); its 2 pilot units were dropped ($2.02, kept
  locally in `long-pilot-dropped.jsonl`, counted in the total). The 3 self/ccx units already run were kept. One ccx unit
  running when the pilot was stopped never reached the results file (about $0.3, estimated).
- **Long-session tasks cut from 10 to 5**: ~$0.6 a unit, 10 tasks × 3 arms would be ~$18; 5 tasks already show the
  direction (all right, spend within a few cents).
- Chinese text in review notes looked garbled during calibration: a display problem of the local console; the records
  are correct UTF-8, not a ccx bug.
- Round 3's pilot problem ("working folder too deep, the lead's session file not found") was traced and fixed (#119):
  Claude Code cuts project folder names past 200 characters and adds a hash, and the full path passes Windows' 260
  characters.
