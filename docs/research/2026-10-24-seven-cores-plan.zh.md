# 七个核心的测试方案（A/B 与功能验收）

[English](2026-10-24-seven-cores-plan.md) · 中文 · 2026-10-24 · 写于真跑之前；结果见 [2026-10-24-seven-cores-ab.zh.md](2026-10-24-seven-cores-ab.zh.md)

## 0. 目的和原则

用真实运行回答：relayline（`ccx`）的七个核心各自**能 / 部分 / 不能 / 还没测**。原则：

- **不靠自评**：做对没做对由隐藏验收测试决定（智能体看不到），不看智能体或 ccx 自己说的“done”。ccx 自己的判断（`check`、`ok`）单独记下来，用来看 ccx 有没有“说对了其实错了”。
- **事先写好判定规则**（本文第 3 节），跑完照规则判，不按结果改规则。
- **负结果、没测到的都写**。
- 和正在跑的 H11 一周对比（`ccx trial`，到 2026-10-31）分开：本方案的每次 `ccx run` 都带 `--no-ab`，不会被 trial 抽成样本；标签一律是 `eval-7c:*`，trial 只统计带它自己 id 的运行。

## 1. A/B 设计

脚本：`scripts/eval/seven_ab.py`（任务在 `scripts/eval/tasks.py`）。

### 1.1 任务集

| 组 | 任务 | 说明 |
|---|---|---|
| 核心任务（A/B/C 用） | slugify、duration、intervals、cli-json（小，上一轮用过）；inventory、csvstats、lru（中等，本次新加） | 中等任务有 3 条以上要求，inventory 要改两个文件 |
| 记忆任务（D 用） | mem-errors、mem-money、mem-log | 任务说明里**故意不写**一条项目约定（报错类型、金额用整数分、每个函数打日志），隐藏测试检查这条约定 |

每个任务是一个临时 git 仓库：起始代码、可见测试、隐藏验收测试。`tests/test_eval_tasks.py` 在没改过的副本上确认隐藏测试**判为不通过**，参考解判为通过（15 个任务全部确认）。

### 1.2 四组对比（B − A，即处理组 − 对照组）

| 组 | 对照 A | 处理 B | 固定不变的 | 看什么 | 对应核心 |
|---|---|---|---|---|---|
| (a) deleg | 主会话自己做 | 主会话经 `ccx run` 派给 Codex | 主会话 = 全新无头 Claude sonnet（medium，精简启动）；子智能体 gpt-6-luna low；`--review off` | 总 token（主会话读入+输出 + 子智能体）、总花费、墙钟时间、一次通过率；主会话请求数 × 真实上下文（35.2 万）外推 | 5 |
| (b) route | 固定一个模型：Claude sonnet medium，不升级 | `--to auto --minutes M`：task-routing 选家、模型、档位，失败可升级 | 同一个 `--check`；无主会话，直接 `ccx run` | 通过率、花费、时间、选了谁 | 4 |
| (c) review | `--review off` | `--review on`：另一家的便宜模型读 diff，有问题退回修一轮 | 子智能体 gpt-6-luna low，不升级 | 通过率（主）、花费、时间、审查结论 | 4 |
| (d) memory | 仓库里没有那条约定 | 仓库的项目记忆（`ccx ctx add` → `.ccx/context.md`，ccx 在派活说明里指给子智能体）里有 | 子智能体 gpt-6-luna low，不升级 | 通过率（主）、花费 | 3 |

(d) 的效果某种程度上是构造出来的（没有记忆就不可能知道约定）。它真正检验的是：**记忆能不能送到真实子智能体手里、子智能体会不会照着做**。H5 的“建议记下 → 用户同意 → 写入共享记忆”和共享记忆（hub）进 Codex/Claude 开局 hook 的路径不在这组里：前者等关键路径会话的 H7 确认后作为功能验收，后者会写用户真实的 hub，本轮不做。

### 1.3 分配和重复

- 每组每个任务 **3 轮**（`--rounds 3`）。每轮里任务顺序随机，每个任务的两臂先后随机，种子 `--seed 7` 固定，可复现（`seven_ab.py plan` 打印全部顺序）。轮次在外层，所以中途停下时每组都已有前几轮。
- **配对**：同一组、同一轮、同一任务的两臂是一对。每臂都是全新临时仓库、全新会话。
- 每跑完一个单元立即追加到 `.ccx/eval/seven/results.jsonl`（不进 git，里面有本机路径），再跑会跳过已完成的单元（续跑）。隐藏测试的结论用 `ccx verify` 记进账本。

### 1.4 独立实验单元与统计

- **主分析的独立单元是任务**（核心任务 n = 7，记忆任务 n = 3）：每个任务把 3 轮的配对差取平均，再对任务做符号检验和自助法 95% 区间。同一任务的 3 轮是重复测量，不是独立样本。
- 次要分析在配对层（n = 21 / 9）报告中位数差、区间、符号检验，只作描述。
- 通过率：每臂 Wilson 95% 区间；配对用精确 McNemar（不一致对 b、c）。
- 效应量：配对差中位数、平均差、B/A 比值中位数；通过率差。
- 比较次数：4 个主检验（(a) 总花费、(b) 总花费、(c) 通过率、(d) 通过率），用 Holm 校正；其他指标只描述。
- 任务很小、样本小（n = 7 时符号检验最小 p = 0.016），不显著不等于没有差别；显著也只说明在这类任务、这些模型上成立，不推到真实长对话。

## 2. 功能验收（第 1、2、7 条）

| 核心 | 验收 | 原始证据 |
|---|---|---|
| 1 互为组长和子智能体 | Claude 组长 → Codex 子智能体（(a) 的 delegate 臂）；Codex 组长（`codex exec`）→ `ccx run --to claude` 子智能体，各做一个任务，隐藏测试通过 | 账本 `caller`/`to`、隐藏测试结果 |
| 1（第二轮） | Gemini、DeepSeek 等接口合并后作为子智能体各跑一组 | 同上 |
| 2 两个模型直接对话 | `ccx discuss`（PR #23 合并后）：至少两家各发言、互相回应对方的点、给出结论 | 讨论记录原文 |
| 7 不丢 | 子任务跑到一半被杀掉，`ccx task resume` 接上并做完 | 任务文件、两次运行记录、隐藏测试 |
| 7 可控：撤销 | 一次写入运行后 `ccx undo --apply`，文件逐字节回到运行前 | 运行前后的哈希 |
| 7 可控：花费上限 | `--budget` 设很小、要求并行，子智能体自己的子智能体一花钱就被停下，`kind = over_budget` | 运行记录 |
| 7 不乱 | 全部 A/B 单元里，ccx 说“通过”但隐藏测试失败的次数 | results.jsonl |

## 3. 判定规则（事先定好）

| 结论 | 条件 |
|---|---|
| **能** | 主检验 Holm 校正后 p < 0.05，方向有利；通过率不降（不一致对里对 B 不利的不多于有利的） |
| **部分** | 方向有利但区间含 0；或只在某些任务、某种组长、或外推后成立；或功能验收部分通过 |
| **不能** | 方向不利且区间不含 0，或功能验收失败 |
| **还没测** | 没有数据（依赖没合并、额度不够等），写明原因 |

第 5 条“省”看 (a)：总花费和总 token 两个都要看；如果小模型实测不省、只有按真实上下文外推才省，判“部分”。第 6 条“越用越准”需要按时间的数据（判定越多，路由越准），本轮没有对照设计，只报告账本里的判定数量和自动判定被推翻的比例，判“还没测”或“部分”。

## 4. 花费

总计不超过 $10（API 等价美元：Claude 用 `claude -p` 报的 `total_cost_usd`，子智能体用账本 AE$）；脚本每个单元开始前累加，到 `--budget` 就停。第一轮预算 $6，第二轮（Gemini/DeepSeek）其余部分；DeepSeek 每天不超过 $1。Codex 本周额度紧，只用 gpt-6-luna low。

## 5. 复现

```
python scripts/eval/seven_ab.py plan --rounds 3 --seed 7
python scripts/eval/seven_ab.py run --rounds 3 --seed 7 --tag r1 --budget 6
python scripts/eval/seven_ab.py summary --tag r1
```
