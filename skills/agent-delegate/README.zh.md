# agent-delegate（中文说明）

[English: SKILL.md](SKILL.md)

**作用**：通过 ccx 执行已获授权的跨智能体委派，并验收结果。仅要求拆任务或省 token 不触发委派。

**和另外两个技能的分工**：
- **task-routing**：决定谁做、用哪个模型、用哪档强度、要不要拆开。
- **agent-delegate**（本技能）：负责怎么写简报、怎么派、怎么收、怎么验收。
- **task-checkpoint**：长任务中途断了，从断点接着做。

**主智能体自己要省**：派任务只需要这个技能和简报，别为了派任务去读项目的 README、STATUS、handoff 或文档。简报里写文件名，子智能体自己去读（还会读 `.ccx/context.md`）。找不到 ccx 命令时才看 `ccx -h` / `ccx run -h`。

**最大的花费是主智能体自己的上下文**：每一轮都要把整段对话重读一遍。大块阅读（很多文件、长日志、查资料）用只读派出去，只拿回结论；对话已经很长、接下来又是新的一块活时，交接给新会话：先问用户，再运行 `ccx fresh`（用这段对话自己的记录文件写交接，在本目录新开的对话开局就能看到）。输出很长的命令（跑测试、看日志、`git diff`）用 `ccx sum -- <命令>`：只拿到失败项或按文件的摘要，全文留在磁盘上。`ccx lead` 能看到你现在每一轮花多少，`ccx lead --breakdown` 看每轮重读的都是什么。

## 步骤

1. **沿用已确定的选择**：保留获准的目标、模型、强度和读写范围。指定模型时跳过路由；确实需要选模型才用 task-routing，需要拆任务才用 task-split。必须固定目标/模型时使用 `--no-escalate --no-fallback`。并行也须在授权范围内。
2. **写简报（≤200 字）**：写明目标、要看的文件、限制条件、怎么验证、怎样算做完。引用现有原件，复用已有 `.ccx/context.md`；只有上下文维护属于本次授权时才更新它。
   - **用户说到某个项目但没给路径**（“那个桌宠”“harness 那个 PR”）：先 `ccx where "<用户原话>"`（只用代码、不花钱）。只有一个 `pick` 就用它；几个候选就问用户是哪个。派进去用 `ccx run --project <名字>`：进那个目录，简报开头带上它的规则文件。项目规则里讲到审批时，ccx 先停下、原样列出（`approval_rules`），由你按规则判断或问用户，之后才加 `--rules-ok` 重跑。
3. **运行**：`ccx run`（带打分参数时自动选模型；默认允许改文件）、`--model/--effort`（自己指定）、`--mode read`（只分析）、`--check CMD`（验收命令，子智能体跑完 ccx 再跑一遍）、`--risk visible` / `--review on|off`（由另一家的便宜模型审改动；auto 时风险高、代码改动 50 行以上、子智能体没把握、说的和实际改动对不上，或证据弱（验收命令放过过做错的结果、或只有子智能体自查，每天最多 20 次）才审）、`--worktree`（在单独的分支上改）、`--task/--step`（会话 ID 一出现就写进 task-checkpoint）、`ccx batch`（并行）、`ccx resume`（在同一个子会话里追问，或从中断处接着做）。
   - 额度用完/限流：自动换另一个智能体再试一次（`--no-fallback` 关掉）。
   - 超时或崩溃：会话 ID 已经存下，`ccx resume <run_id>` 接着做。
4. **验收**：子智能体的总结只是它的说法。核对改动或返回证据，同一产物的有效检查可复用，缺失、过期或有矛盾时再补跑相关检查；`not-run` 就照实告诉用户“没验证”。**结果里的 `check` 显示 ccx 已经跑过你给的 `--check` 并且通过时，主智能体不要再自己重跑一遍**，看 `check` 结果和改动就行：主智能体每多一轮都要重读整段对话；H11 实测（2026-10-24）里，派完再自己重跑验收的主智能体一点没省，信 ccx 验收结果的每个任务少一轮。只补跑验收命令没覆盖到的部分。如果 `check` 里带 `weak`，说明这个验收命令在这里放过过做错的结果：要对照任务看改动，不能只看 check。然后 `ccx verify <run_id> --ok 1|0`：这一步会校准路由（给了 `--minutes` 还会校准拆分），并把 checkpoint 的这一步标成完成。做错时可以加 `--reason unfinished|wrong|overreach|other`（没做完 / 做错了 / 改了不该改的 / 其他）。没人判断的运行，过 12 小时后如果 ccx 的验收命令或子智能体的自查通过、审查（如果有）也通过，会自动记成“大概率对”；被 `ccx undo --apply` 撤回的不自动记对错，等你判；撤回时加 `--wrong` 就同时记成“错”。你自己的判断永远优先，所以只要真的看过，就记一下。结果里的 `review` 是独立审查的结论：`pass` 或 `issues`（带文件:行）；改过一轮还不过会标成 `review_failed`，由你决定。
5. **换主智能体**：用户说“交接给 X”时，自己还能写就 `ccx handoff --by <你> --to X "…"`；原主智能体写不了（额度用完、崩了、窗口关了）就 `ccx handoff --from-transcript <原主智能体> --to X`，由代码从它的会话文件整理。接手方先核对其中的说法（文件在不在、测试过没过）。
6. **记忆**：只有记忆维护已获授权时，才用 `ccx mem add` 保存必要的长期事实；委派任务本身不授权写入记忆。
