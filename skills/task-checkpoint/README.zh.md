# task-checkpoint（中文说明）

[English: SKILL.md](SKILL.md)

**作用**：长任务跑到一半时，可能额度用完、电脑死机、窗口被关，或者需要换另一个智能体接着做。这个技能保证下次能从断点继续，已经做完、验证过的步骤不用重跑。

**可以单独用**：整个文件夹复制到任何 Claude Code、Codex 或其他智能体的技能目录就能用。只需要 Python 3.11+，git 可选，不依赖 ccx。

## 记了什么、放在哪

| 内容 | 文件 | 说明 |
|---|---|---|
| 每一步的状态（未开始 / 进行中 / 完成 / 中断）、谁做的、会话编号 | `.ccx/tasks/<任务>/plan.json` | 原子写入（先写临时文件再替换），写到一半崩了也不会损坏 |
| 事件流水 | `progress.jsonl` | 只追加，每条立刻写入磁盘；最后一行写坏了会自动跳过 |
| 续跑简报 | `checkpoint.md` | 新会话只读这一份，几百 token |
| 心跳 | `lock.json` | 超过 10 分钟没更新的“进行中”步骤，判定为中断 |
| 代码快照 | git 的 `refs/checkpoints/<任务>/…` | 用 `git stash create` 生成，**不动你的分支、暂存区和文件**；续跑时用 `git diff <快照>` 看从那以后改了什么 |

## 怎么判断发生了什么

- 能看到的停止（额度用完、报错、被挡住）：用 `fail --reason quota|error|blocked` 记下原因；额度类可以带上恢复时间。
- 看不到的停止（死机、断电、直接关窗口）：心跳超时，自动判定为 `interrupted`。

## 续跑顺序

1. `status --quiet` 列出未完成的任务；没有未完成的任务就什么都不输出。
2. `brief <任务>` 看续跑简报。
3. 跳过已完成的步骤。
4. 中断的那一步，优先接回原来的会话（它记得自己做到哪）：用 `ccx run --task <任务> --step <n>` 派出去的步骤用 `ccx task resume <任务>`：窗口被关或崩溃后也能找到那次运行并接回会话；会话还没开始就被杀的会重开这一步；额度中断时换另一个智能体，带上简报和 diff 接着做（加 `--same` 则坚持用原会话）。其他情况用该 CLI 自己的续接命令；接不回就从简报和代码快照的差异重新开始这一步。

## 局限

- 当前这一步里还没写下来的思考会丢；最后一次 `done` 之前的内容都是安全的。
- 一个智能体的会话不能交给另一个智能体续，只能靠简报和代码差异交接。
- 不是每次额度报错都会给出恢复时间。
