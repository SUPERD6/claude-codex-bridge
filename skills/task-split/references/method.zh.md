# 方法：怎么定量地拆任务

[English](method.md) · 中文

## 1. 成功率与每块的长度（METR 时间跨度）

Kwa 等（METR，2025）把智能体的成功率拟合成“任务长度取对数”的逻辑函数：

```
p(t) = σ(β · (ln h50 − ln t)) = 1 / (1 + (t / h50)^β)
```

- t 是任务长度，用“人类需要的分钟数”表示。h50 是智能体有 50% 把握做完的任务长度。
- 他们报告：80% 成功率对应的长度，比 50% 的短约 4–6 倍。取 5 倍，由 σ(β·ln 5) = 0.8 解得 β = ln 4 / ln 5 ≈ 0.86。
- 成功率还能保持 p* 的最长一块：t_max = h50 · ((1 − p*) / p*)^(1/β)。p* = 0.8 时约为 h50 / 5。
- 时间跨度大约每 7 个月翻一倍，所以 `data/horizons.toml` 里的 h50 是带日期的估计，会被实测值替换。

## 2. 拆成几块：看“每成功一次的花费”

把 T 分钟的任务拆成 n 块，每块 t = T/n。每块都要付一笔开销 o：写简报、启动、检查、交接。

**能检查的块**（有测试能判断成败）：失败的块可以重试，最多 3 次：

```
p_块    = 1 − (1 − p)^3
尝试次数 = p_块 / p
花费(n) = n · (o + t) · 尝试次数
P(整体) = p_块^n
选 n    = 使 花费(n) / P(整体) 最小，且满足 p(t) ≥ 0.8
```

**不能检查的块**：没法重试，错误不会被发现，会一层层累积：

```
P(整体) = p(t)^n
```

因为 β < 1，n 越大，P(整体) ≈ exp(−n^(1−β) · (T/h50)^β) → 0。**不能检查的工作切得越碎，整体越容易失败。** 这就是规则 2（“只在能检查的地方切”）的定量依据。

## 3. 在哪里切：耦合与交接

Anchan & Sen（2026）用两种成本来描述拆分：
- **注意力税**：单个智能体的上下文越长，每一步出错的概率越高。
- **交接税**：每一块都只能从摘要开始，而不是完整的工作现场。

只有当避免掉的注意力税超过付出的交接税时，拆分才划算。落到实践上：
- 在需要跨边界传递的信息最少的地方切，也就是耦合低的地方。这是经典的模块化 / 设计结构矩阵（DSM）准则。
- 输入依赖很多的块会被标记出来。

并行的块如果改同一个文件，最后还得合并改动，所以也会被标记。

## 4. 什么时候切：按需

ADaPT（Prasad 等，NAACL Findings 2024）先把任务整体交给执行者；只有执行失败时，才用“与/或”逻辑拆成 3–5 个子任务，并递归到最大深度。在 ALFWorld、WebShop、TextCraft 上，它比“先全部规划好”的做法高出最多 28–33 个百分点。

E3（Yin & Feng，2026）对写代码的智能体得出同样结论：先估计够用的最小范围，走精简路线，只有检查失败了才展开。

所以这里的规则是：先分 3–5 个里程碑；只有某块失败了、或明显超过时间跨度时才往下拆；最多 3 层。

## 5. 并行时间（工作量 / 关键路径）

计划里的依赖关系构成一个有向无环图（DAG），`check` 按下面的方式处理：

- 把各块分成“波”，同一波可以并行。
- 算出总工作量 W 和关键路径长度 S。
- 给出 w 条并行通道时的墙钟时间范围：max(S, W/w) ≤ T_w ≤ W/w + S（Brent 定理）。
- 加速比 = W / max(S, W/w)。关键路径很长时，加通道没用，应该缩短依赖链。

## 6. 校准（自动）

每块验证完之后（`split_plan.py record`，或者 `ccx run --minutes M` 被验收时自动记录）：

```
ln h50 ← ln h50 + 0.3 · β · (y − p(t))
```

这是逻辑回归对数似然在 ln h50 上的一步梯度：模型“本该”失败的块做成了，h50 就往上调；简单的块失败了，就往下调。学到的值通过 hub 两边共用。
